# 项目代码审查与加载修复

审查日期：2026-10-17。范围包括 `employee-off-work/assets/scripts` 下的游戏模型、操作与教学、界面绘制、音频与平台服务，以及双端启动构建、开放数据域和回归脚本。保留原有玩法、难度与现有音效修改，未手工修改场景、Prefab 或资源 UUID。

## 已修复的问题

| 问题 | 原因及修复 |
|---|---|
| 首屏进度条长期不动 | 旧微信首屏关闭了动态条，展示的是原画里固定的绿色条；大部分时间消耗在引擎及美术分包预取，场景加载器尚未接管。现在用同一张原画的轨道、绿色条和鱼轮廓动态绘制，并接入真实分包下载与资源完成进度。 |
| 交接时进度跳回、画面闪动 | 启动海报与场景的进度独立，浏览器封面在实际绘制前就被移除；微信两套 RAF 及 WebGL 状态交接不完整。现在继承已显示的进度，微信进入引擎帧循环后串行呈现首屏，准备好场景加载画面时同步停止首屏；恢复绘制涉及的 GL 绑定、裁剪、视口和颜色写入状态。浏览器封面保留到场景帧完成绘制。 |
| 资源完成后直接跳首页 | 分离“资源完整”和“可以操作”状态，让真实进度平滑达到 100%，至少绘制一次满格条后再显示首页。不会通过假进度越过实际完成量。 |
| 启动依赖隐式全局 `cc` | 旧微信交接回调引用另一个 Promise 回调内的 `cc`，只能依赖环境额外暴露的全局变量。现在在引擎导入回调内注册交接，绑定同一个引擎实例。 |
| 销毁或失效加载后仍继续重试 | 销毁时立即递增加载代次，加载器在每次重试前校验代次，迟到结果不再回写界面；启动预取超时后忽略迟到的分包回调。 |
| 菜单触摸跨后台残留 | 过去只有进行中的游戏在切后台时清理触摸。现在首页、加载重试、结果页也统一取消触摸和待执行按钮，回前台松手不会误启动。 |
| 致命碰撞后仍拾取、减负或加分 | 致命碰撞发生后立即结束该帧的规则处理并回收已失效对象，避免“已失败却又被同帧 Agent 减负”等矛盾状态。 |
| 无效帧时间污染动画 | 帧入口过滤负数、NaN 和 Infinity，正常动画时间保持原口径。完整回归发现初版上限影响头像过渡，最终版本已去掉该上限并复验。 |
| 损坏存档阻止分数同步 | 分数、波次、局数限定为非负安全整数，秒数仍允许正常小数；不合法字段回退，保留其他有效进度。 |
| 本地预览服务崩溃或越界 | 捕获损坏 URL 编码和构建期间文件替换；使用路径相对关系检查边界，拒绝访问同名前缀的兄弟目录，并补齐图片、音频 MIME。 |
| 微信恢复测试误判 | 验证脚本把应用返回的 `ready:false` 当成“场景不存在”，无法检查预期的失败状态。改用独立的场景等待标记，修正重试按钮坐标，离线注入仅作用于美术分包且在第三次失败后恢复原加载器。 |

核心修改位于 `GameMain.ts`、`PlatformServices.ts`、`model/AsyncLoading.ts`、`model/GameModel.ts`、`model/GameExperience.ts`、`scripts/startup-art.mjs` 和 `scripts/startup-screen.mjs`。
