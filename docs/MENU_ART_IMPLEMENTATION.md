# 加载封面、首页与结算美术接入

日期：2026-10-14。沿用 Cocos Creator 3.8.8、720 逻辑宽度与现有场景；新增节点、纹理切片及布局均在 TypeScript 中创建。

## 资源与流程

三张确认版 PNG 逐字节复制到 `employee-off-work/assets/art/menus/`：`loading.png`、`home.png`、`result.png`。原始文件保持不变，SHA-256 对照记录在 `employee-off-work/temp/qa/menu-art/source-verification.json`。新增资源的 `.meta` 由 Creator 构建时自动导入生成。

- 启动先显示图 1 的加载封面；资源就绪后显示图 3 的首页，首次玩家不会自动跳入教学。
- 点击“开始摸鱼”后，未完成当前教学的玩家进入原有操作教学；已完成教学的玩家直接开始正式对局。
- 没有正式对局记录时，首页整条“个人最佳记录”隐藏。使用原图顶部与底部的运行时切片缩短卡片，移除空行；首局结算后恢复记录栏，数字读取本地最佳分数。
- 图 2 用作结算卡片。示例分数、评级、评级印章、时长、波次、连击、穿缝／甩脱次数、下一局目标由运行数据替换。“再来一局”沿用重新开始逻辑。
- 卡片在屏幕中居中，按可用宽高等比例缩放；按钮点击范围同步缩放。首页的好友积分榜与操作教学并排放在卡片底部，结算页的好友积分榜居中放在卡片底部。两页音效开关及结算页返回首页入口删除；暂停设置仍保留音效控制。

首页、结算页的整图显式创建未裁切的 SpriteFrame，避免 Creator 自动去透明边后导致文字覆盖错位。个人记录栏的隐藏、示例数值的覆盖和评级印章均不修改原始图片。

结算页每次显示时重新定位数值覆盖区域，避免资源异步加载期间先显示了缩短的首次首页，导致结算覆盖位置沿用首页高度。评级覆盖区域收在卡片内沿以内，保留右侧边框。

## 启动与加载

`scripts/startup-art.mjs` 在每次成功构建后设置浏览器启动封面和微信 first-screen 背景。仅将构建目录中的启动封面副本编码为 JPEG（1080×2400、质量 92，约 0.7 MB）；资源目录中的确认版 PNG 保留原样。

运行时显示实际资源加载阶段的进度与移动小鱼；资源未就绪时不能开始对局。原有三次自动重试、超时保护和失败后的点击重试继续生效。平台启动代码及浏览器封面交接分别位于构建脚本和平台服务层，核心游戏规则没有新增 `wx.*` 调用。

加载条修订：移除额外叠加的加载面板及重画的进度条。封面只显示一次，进度条沿用原图的边框、空槽、绿色纹理和小鱼；仅在原条内部更新填充，小鱼使用原图纹理和轮廓遮罩。整幅封面等比例完整显示，加载条与封面共用坐标和缩放，短屏也不会裁掉底部加载条。正常加载不再叠加百分比文字，失败后的重试提示仍保留。

## 2026-10-15：结算入口居中与文件夹层级

- 结算页好友积分榜按纸卡主体及“再来一局”的横向中心定位。原图右侧猫猫和咖啡杯造成图像整体中心与纸卡中心不同，按钮现使用主按钮的中心坐标，文字与点击范围同步移动并随卡片缩放。
- 用户截图中缺口附近的类似边框效果来自 `FolderGapEdges` 的紫色／米白描边提示，现已移除该节点及绘制逻辑。
