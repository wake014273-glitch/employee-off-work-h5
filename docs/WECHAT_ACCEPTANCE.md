# 微信小游戏当前版本真机验收

本表用于体验版验证，不代表上架验收。每轮先运行项目检查，再用**本轮新生成的体验码**测试；旧二维码可能仍指向旧包。记录 `employee-off-work/build/wechatgame/build-info.json` 的 `fingerprint`，并与 `npm run qa:wechat` 报告中的值核对。开发者工具通过不等于物理手机通过。

当前开发者工具自动截图接口在多阶段回归中会返回黑图或旧帧；`qa:wechat` 因此只将运行时状态和操作断言列为自动化证据，不保存阶段截图。美术清晰度、触控手感、性能和加载体验必须按下表在真机验收。

构建脚本按原始产物字节数限制主包不超过 4,000,000 字节、主包加分包不超过 20,000,000 字节。后者来自 2026-10-16 开发者工具预览上传实测：原包约 25,477 KB 被以“source size exceed max limit 20MB”拒绝。`npm run audit:size` 展示细项；这是为预览留余量的本地门槛，最终仍以微信开发者工具上传结果为准。58 张美术 PNG 已在保持像素尺寸与资源 UUID 的条件下压缩；检查时还应观察文字边缘、半透明叠层和加载封面的画质。

## 设备与网络

至少一台低端 Android、一台常见 Android、一台 iPhone；每台记录机型、系统、微信版本、可用存储和网络。每台测试 Wi-Fi 冷启动与移动网络冷启动，再测二次启动。冷启动前清除小游戏缓存或使用首次安装环境，并说明具体做法。记录从点击入口到可操作首页、从点“开始摸鱼”到教学可操作的秒数；失败或超过 30 秒保留录屏和控制台日志。30 秒是本轮诊断界线，不是已验证的产品性能目标。

## 必走流程

1. 首次打开：启动图、下载进度、失败后的“重新加载”、首页画面与声音正常；无 Cocos 标志页卡死、黑屏或触摸失效。
   本轮重点复测首屏交接：清除小游戏缓存后录屏，确认自定义加载图持续显示到游戏加载画面或首页出现，中间没有纯深蓝空白或加载图闪回；再做一次热启动对照。此前 iPhone／微信 8.0.69 上的空白约 6 秒。记录手机系统、微信版本与空白持续时间。
2. 首局教学：拖动、拾鱼、双击护盾、AI 工具，完成后进入正式对局；教学不增加对局次数。
3. 正式对局：第 8 秒进入一般阶段，第 24 秒进入困难阶段；暂停与后台恢复期间计时、护盾和弹幕不跳时；重新进入后手指能继续拖动。
4. 结算与主动退出：三次受击显示成绩单；第 10 秒退出后的下一局目标应指向第 3 波。另一局暂停并确认返回首页后，个人最高分、最长时长、最远波次和对局次数已保存；取消退出不保存或重置。
5. 好友榜：使用两个有体验权限且互为好友的微信账号验证授权、双方成绩、排名、刷新与断网后重试；再用同一账号跨设备核对最高分。当前托管数据并发写入不提供跨设备事务，测试时记录这一限制。
6. 长局：在至少一台低端 Android 上连续玩 10 分钟，记录帧率、明显卡顿、内存峰值、发热和音效中断。建议先以低端机稳定 30 FPS、普通机稳定 60 FPS 为产品目标；若设备不能持续达到，先记录瓶颈再调整资源或特效。
