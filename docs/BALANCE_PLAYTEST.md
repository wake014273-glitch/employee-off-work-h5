# 难度与评级试玩记录

当前规则见 `WAVE_SYSTEM.md` 2.2，当前评级门槛见 `employee-off-work/assets/scripts/model/GameModel.ts` 的 `rankFor`。在拿到玩家数据之前，**不调整** S/A/B 门槛或困难曲线，以免把模型压力测试当作真人体验。模型五分钟测试持续赋予角色无敌，仅验证数值和对象有界。

## 样本与记录

邀请至少 10–20 位此前没有玩过本作的人，记录每人的前三局；不要教其未在游戏内呈现的操作。每局记录构建指纹、设备、存活秒数、分数、最高波次、评级、三次受击时刻、是否用过护盾、鱼／请假条／AI 工具的看到与取得次数、第一次不明白的界面或操作。玩家主动退出单独标记，不能与失败局混算。

| 玩家／局次 | 设备 | 秒数 | 分数／波次／评级 | 护盾使用 | 道具看到／取得 | 死亡或退出原因 | 不理解之处 |
|---|---|---:|---|---|---|---|---|
| | | | | | | | |

汇总首局及前三局的时长中位数和 90 分位数、到达困难阶段比例、在 3:24／6:24／9:24 后仍存活比例、各评级比例、拥有满盾但未使用的比例，以及首个失误类型。S 最早约 9:24、A 约 6:24、B 约 3:24 只是由波次门槛推算的时间，分数和 S 操作评价仍是额外条件。

## 调整决策

先选一个玩家体验目标，例如“首次玩家至少能理解护盾、熟练玩家能稳定达到 B”，再检查记录是否支持。若大量玩家在第 24 秒前死亡，先查教学和早期可读性；若大多数人在 3 分钟前死亡，不应只下调评级分数；若能活过门槛却长期拿不到分数，检查风险换分和波次奖励。每次只改一个参数组，记录旧值、新值、原因，并用同一组玩家任务与自动化回归复测。

此外，用正常玩法录屏分别验证擦弹、穿缝、甩脱能触发 B/A/S 操作评价；不能只通过直接设置模型字段证明评级可达。
